## 0. The one-paragraph verdict

Àlááfìa is a **research prototype presented as a product**. The read endpoints are healthy and the geography lookups are correct, but the "causal AI" underneath is an LLM narrating plausible stories from **2–3 simulated individuals per geography**, graded by a **keyword counter** that awards "A" to 17 of 18 zone findings whose own records disagree with each other, and an **equity layer that is structurally guaranteed to produce cross-zone claims** — which is why **44% of zone pages and 59% of state pages describe a region that isn't theirs**. That data is served publicly right now. Separately, the live `/analyse` route has an **authenticated code-injection hole**. The database side is clean and tiny: 3 rows, all internal test data.

## 3. The critical one — cross-zone misattribution (#1)

**Re-measured today:**
- Zone file: **8 / 18 entries (44%)** contain prose that names a geopolitical zone other than their own.
- State file: **66 / 111 entries (59%)**.

Examples straight from the served JSON:
- `state_1:anaemia` — Sokoto (North **West**) — pathway text: *"…reduced parity and lowered severity of anaemia in women…"* with `beyond_poverty` / driver text referencing **North-Central** and **South East**.
- `NW:stunting` — North West — text references **SE** and **SS**.
- `NE:wasting` — North East — text references **SE**.

**Root cause — this is by design, not a join bug.** The earlier audit suspected a data-join error. It isn't: `utils/nigeria_geography.py` and `utils/data_filter.py` map states→zones **correctly**, and `filter_by_geography` filters records correctly. The contamination comes from **`agents/equity_interrogation.py`**:

1. `interrogate_pathway_equity()` (`:62–107`) hands the model **all six zones' outcome numbers** and asks *"which zones have higher exposure and why"*. The model, prompted to compare across zones, naturally writes prose naming NC/NE/SE/etc.
2. `precompute.py` (`:149–151`) then stores that cross-zone prose (`equity_driver`, `beyond_poverty`, `structural_recommendation`) **under a single geography's key**.
3. `wealth_stratified_analysis()` (`:125–147`) goes further — it **hardcodes the conclusion** (*"This means SE anaemia is NOT primarily a poverty problem"*) and a template with `"poverty_explains_disparity": false` already filled in, then asks the model to elaborate. Every `beyond_poverty` field is the model dressing up a pre-written answer.
4. `highest_impact_intervention_zone` (`:104`) is computed by `max()` over the **hardcoded** `ZONE_PROFILES` dict and string-injected into the response — a deterministic constant presented as an AI equity finding.

So a policymaker on the Sokoto page can be shown a causal claim explicitly about a zone 700 km away with the opposite epidemiological profile. **This is the one issue here with real-world decision consequences, and it is live.**

Fix direction: the equity layer must be scoped to one geography's own data, or its cross-zone output must be stored as a separate "national comparison" object — never merged into a single geography's card. And the hardcoded conclusions in `wealth_stratified_analysis` have to go.

## 4. The causal pipeline (Python)

### 4.1 It does not do causal inference (#5)
`run_pipeline()` = three `ollama run` shell-outs. Proposer (`llama3.1:8b`) gets one woman's `|`-joined tag string + a hardcoded `NIGERIA_PRIORS` block and is asked to emit a DAG as JSON. Critic challenges it. Judge (`natlas`) picks a final sentence. **There is no dataset in the loop beyond one row, no confounder adjustment, no effect estimation, no counterfactual.** The `stats` block attached to each entry (n ≈ 9,000 real DHS records) is real; the pathway next to it is one LLM's story about one person. The credibility of the page comes from that juxtaposition.

### 4.2 n = 1–3 (#4)
- `precompute.py`: 6 zones × 3 outcomes × 5 wealth groups × **3 records** = up to 270 LLM runs, then `dominant = max(all_pathways, key=quality_score)` — the displayed finding is **one** record's pathway. `total_records_analysed: 14–15` counts the runs, not agreement.
- `precompute_states.py`: **3 records per state**, dominant = 1. `n_records_analysed: 2–3`.
- Samples use fixed seeds (`random_state=42` / `99`), so they are 3 *fixed* draws, not 3 random ones — re-running doesn't resample.
- `precompute_states.py:88–89` only applies an outcome filter for `anaemia`; stunting/wasting pathways are built from women sampled without regard to whether an under-5 child with anthropometry exists.

### 4.3 The quality grade is theatre (#3)
`validation_framework.evaluate_pathway_quality()` scores four dimensions purely by **substring matching**:
- *biological_plausibility*: +1 if the sentence contains `"via"`/`"causing"`/… (the model is prompted to write exactly those) ; +1 if `key_mediators` non-empty (always) ; +1 if it splits on `→` into ≥3 (never, for prose) → ~0.67 floor.
- *directionality*: 1.0 unless both halves of a known-bad pair appear verbatim → ~always 1.0.
- *confounder_awareness*: counts confounder names; proposer is **required** to list ≥3 → 1.0.
- *nigeria_specificity*: counts `"zone"`, `"south"`, `"nigeria"` … the sentence starts *"This woman from the South East zone…"* → 1.0.

Typical total ≈ 0.9 → **Grade A**. The prior audit's "improved sanitation causes stunting" (backwards, nonsensical) would still score A — it has "causes", a mediator, confounder words, and "zone". Measured: **zone file 17/18 Grade A, and all 17 have `records_agree: false`; 16 have `pathway_consistency ≤ 0.5`.** The grade is inversely related to nothing.

`aggregate_pathways()` (`precompute.py:69`) compares `pathway[:40]` — the first 40 chars of every pathway are *"This woman from the {zone} zone, being"* — so `records_agree` / `pathway_consistency` skew toward "agree" for reasons of sentence template, not content.

### 4.4 Portability / reproducibility (#12, #13, #17)
- **No `requirements.txt` / `pyproject.toml` / `Pipfile`** anywhere. Dependencies (`pandas`, `numpy`, `pyreadstat`, `ollama`, the two local LLMs, the `N-ATLaS.Q4_K_M.gguf` weights) are undocumented.
- 40+ hardcoded `/Users/theoneglobal/...` — `sys.path.append` (7 files), data paths, `models/natlas/Modelfile:1` (`FROM /Users/...gguf`), and `utils/outcome_map_complete.py:19–23` which does `exec(open('/Users/.../outcome_map.py').read())`.
- **`scripts/precompute.py:28` and `precompute_states.py:25` write into `/Users/theoneglobal/Iyawo/backend/src/data/`** — the pipeline's output path is inside the *other* repo. Broken now.
- `merge.py` → `merge_all.py` → `merge_mr.py` each read and **overwrite the same `ndhs2024_merged.parquet` in place**, in an order that exists only in someone's head. Running twice or out of order corrupts it. No `Makefile`, no orchestrator, no backup.
- Two different "stunting %" computations coexist: `eda_summary.py:17` filters `|z|>6`; `merge_all.py:36` does `((x/100) < -2).mean()` with no missing-flag filter. They produce different numbers; the site shows the second.
- `tokeniser.py` has **29 bare `except:`** — any field parse error silently drops that tag, so "no exposure" and "data missing" are indistinguishable to the model. Missing water/sanitation codes fall through to `"unimproved"` / `"poor"` (`:63,74`).
- `causal_agents.ask_ollama` and `equity_interrogation.ask_ollama` are copy-pasted; neither handles `ollama` being absent (`subprocess.run` raises uncaught).

### 4.5 Priors drift (#6)
Zone statistics are hand-typed in three places:
- `causal_agents.py:16` `NIGERIA_PRIORS`
- `equity_interrogation.py:19` `ZONE_PROFILES` and `:28` `WEALTH_ANAEMIA`
- computed for real by `utils/eda_summary.py`

Nothing links them. Values already disagree (e.g. NC unimproved-water appears as 33.6 in one place, absent in another). Whatever `eda_summary.py` produces today, the prompts still use June's transcription.

### 4.6 Method claim vs implementation (#20)
`agents/natlas_role.md` is a careful doc — it explicitly says N-ATLAS "does not adjudicate on biological mechanisms… does not evaluate statistical validity." But `dag_judge`'s prompt (`causal_agents.py:149`) tells N-ATLAS to *"Accept strong edges. Reject weak ones."* — mechanism adjudication. And the doc's validation plan (compare against a Llama judge, have Nigerian epidemiologists rate outputs, document wins) has no corresponding code or results file.

## 5. The extracted backend (Node)

### 5.1 `/analyse` code injection (#2) — **High**
`backend/src/routes/alaafia.js:58–92` builds a Python program by template-string interpolation:
```js
geo_value = '${geoValue}'
```
`geoValue` / `geoType` / `outcome` come from the request body and are checked only for presence (`:182`). An approved key holder can send `geography_value` containing `'); <python>; ('` and run arbitrary code on the pipeline host. It's inert **only** because no pipeline host exists yet — it becomes live RCE the moment `/analyse` is deployed for real. Fix: pass inputs as `argv`/stdin JSON to a *static* script file, never string-build the program.

### 5.2 The live-pipeline half is dead + broken (#8)
`/analyse`, `/job/:id`, `/cached`, `runPipelineAsync` — the frontend calls **none** of them (it uses only `/precomputed`, `/precomputed-states`, `/alaafia-access`). And they can't work: `spawn('python3', …)` in a Node deploy, `PIPELINE_PATH` now a guess, `JOBS_STORE=/tmp/...` wiped every restart, `RESULTS_STORE` never exists, and the spawned script calls `run_pipeline(token, outcome, zone=…, verbose=False)` while `causal_agents.run_pipeline` has no `verbose` parameter → `TypeError`. This whole block is a documented capability that has never run in production.

### 5.3 Access system
- API keys plaintext, looked up by raw value, no hash/prefix (#10). `apiKeyAuth.js` — no constant-time compare (moot given the DB lookup, but no rate-limit either).
- `alaafiaAccess.js` public `POST /` has **no rate limiting** and no captcha — anyone can flood the request table and trigger an email per submission.
- The admin routes (`GET /`, `PATCH /:id`) now require an Ìyàwó **ADMIN** JWT (`verifyToken, requireRole('ADMIN')`) — which means the standalone Àlááfìa service must share Ìyàwó's `JWT_SECRET`. Cross-service coupling; documented in the repo README but worth resolving.
- `email.js` sends from `onboarding@resend.dev` (Resend's shared sandbox sender — poor deliverability, likely spam-foldered) and every template links `curl https://api.iyawo.org/...` → `NXDOMAIN` (#11).

### 5.4 Deploy
- No deploy target for the new repo yet. `backend/Procfile` runs `prisma generate` (correct — the table is Ìyàwó-owned) but nothing hosts it.
- CORS origin list is `iyawo.org` + localhost; fine for now, needs the real Àlááfìa origin later.

## 6. The frontend

- **DAG collapse (#7):** `AlaafiaPage.jsx:1109` and `:1217` do `pathway.split('→')`. The live `pathway` is a prose sentence with zero `→`, so every one of the 129 geographies renders a **single** DAG node containing a ~260-char paragraph in a 190px box (`NODE_W=190`, `:1224`), truncated at the first em-dash (`:1219`). The 4-node DAG only appears when the fetch **fails** and the in-file `PRECOMPUTED` literal (`:41`, arrow-formatted) is used.
- **Hardcoded hero stats (#9):** `:648` `39,050 NDHS 2024 women`, `:649` `31,103 MICS 2021 children`, repeated `:861,1638–1639`. The pipeline processed 14–15 records/zone. **MICS 2021 appears nowhere in the pipeline** — every merge script reads NDHS `.dta` + the GC geospatial CSV; the `eda_mics_*.py` files are unused. "31,103 MICS children" describes data that isn't in the product.
- **Whitespace (#16):** 34% of zone strings / 40% of state strings contain `"  "` mid-sentence — a generation artifact that renders visibly.
- `AlaafiaAdminPage.jsx:10` reads `localStorage['iyawo_token']` (#18) — works only while served from an Ìyàwó origin; on `alaafia.<tld>` there's no such token and the admin page can't authenticate.
- `AlaafiaPage.jsx` is 1,871 lines, one component, no error boundary; the extracted Vite build is 216 KB / 65 KB gz (acceptable standalone, was ~303 KB inside Ìyàwó's shared chunk).

## 8. What is actually fine

- Read endpoints `/precomputed`, `/precomputed-states`, `/outcomes` — fast, stable, correctly decoupled from the (broken) generator. Verified 200 on the extracted backend today.
- `utils/nigeria_geography.py` / `data_filter.py` state↔zone mapping — correct and internally consistent.
- Key **generation** — `crypto.randomBytes(32)` — sound; the weakness is storage, not entropy.
- The admin-secret leak (`alaafia-admin-2024`) — **fixed** on Ìyàwó `main`; `alaafiaAccess.js` uses ADMIN-JWT, no hardcoded secret anywhere in the extracted code.
- No secrets committed anywhere in the repo (checked).
- The extraction itself — backend installs, Prisma validates, server boots, all routes respond; frontend builds and both pages render. Six files are byte-identical to the Ìyàwó originals.
- `natlas_role.md` — as a *statement of intent* it's thoughtful and honest about tokenism risk; the problem is the implementation drifted from it.

## 9. Suggested order of operations

1. **Take the cross-zone data out of the public path** (#1) — either regenerate with the equity layer scoped per-geography, or stop serving `equity_driver` / `beyond_poverty` / `structural_recommendation` until it's fixed. This is the only item actively misinforming anyone.
2. **Before `/analyse` is ever deployed**, fix the injection (#2) — static script, args via stdin.
3. **Stop showing "Grade A"** (#3) until the grade means something, and **surface `computed_at`** and the real n.
4. Fix the hero stats (#9) — real numbers, drop the MICS claim or wire MICS in.
5. Repo hygiene for a standalone project (#12, #13): add `requirements.txt`, parametrise paths, one merge orchestrator, move the output path out of `Iyawo/`.
6. Decide the DB question — `alaafia_access` stays in Ìyàwó's DB (current) vs its own; delete the 3 test rows either way.
7. Fix the DAG renderer (#7) or change the data contract so pathways carry structured edges.
8. Longer term: the n=3 / no-actual-inference problem (#4, #5) is the real methodological work — everything else is patching around it.
